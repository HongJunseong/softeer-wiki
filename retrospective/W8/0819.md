# 2026-08-19 회고

## Keep
- AQE의 Coalescing Post-Shuffle Partitions가 실제 Shuffle 크기에 맞춰 작은 파티션을 병합하는 과정을 확인하였다.
- 파티션 개수가 지나치게 많으면 작은 Task의 스케줄링 비용이 커지고 결과 파일도 잘게 나뉠 수 있다는 점을 이해하였다.

## Problem
- `spark.sql.shuffle.partitions`를 입력 데이터 크기만 보고 고정하면 집계 후 데이터가 크게 줄어드는 작업에 불필요한 Task가 많이 생성되었다.
- 파티션 수를 줄이는 것만 목표로 삼을 경우 일부 Task가 너무 커져 병렬성이 낮아지거나 메모리 부담이 증가할 수 있었다.

## Try
- Advisory Partition Size와 최소 파티션 크기를 조정하면서 Task 수, Task 실행 시간, 결과 파일 크기를 함께 비교하겠다.
- 파티션 최적화의 기준을 개수 자체가 아니라 처리량과 Task 크기의 균형으로 설정하겠다.
