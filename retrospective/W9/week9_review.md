# Week9 회고

9주차에는 앞서 학습한 데이터 파이프라인 설계와 Spark 최적화 내용을 메인 프로젝트의 구체적인 작업으로 연결했습니다. 먼저 사용자와 의사결정 관점에서 문제를 다시 정의하고, 필수 기능과 선택 기능을 구분해 팀 작업의 완료 조건을 정했습니다. 기술을 먼저 나열하기보다 각 기능이 제공해야 할 데이터와 검증 기준을 명시하면서 프로젝트의 범위를 더 선명하게 만들 수 있었습니다.

수집 단계에서는 원천 API의 응답 구조, 갱신 주기, 예외 형태를 확인해 데이터 계약을 작성했습니다. 원본 응답과 수집 시각을 보존하고 Event Time과 Ingestion Time을 분리하여 지연 데이터도 일관된 기준으로 처리할 수 있게 설계했습니다. 정제 단계에서는 표준화와 중복 제거 규칙을 나누고, 각 단계의 건수 변화를 기록해 레코드가 제외된 이유를 추적할 수 있도록 했습니다. 또한 예상 데이터량과 조회 조건에 맞춰 파티션 단위와 결과 파일 크기를 검토했습니다.

운영 관점에서는 최신성, 완전성, 유일성, 유효 범위 지표를 정의하고 장애 상황을 직접 만들어 알림 내용을 점검했습니다. 모든 이상을 같은 심각도로 처리하면 중요한 경고가 묻힐 수 있어 서비스 영향도에 따라 실패와 경고를 나누었습니다. 발표 준비에서는 구현 기능을 모두 보여 주기보다 문제와 핵심 설계 결정, 검증 결과, 남은 한계가 자연스럽게 이어지도록 흐름을 다듬었습니다.

이번 주를 통해 좋은 파이프라인은 정상 실행 화면만으로 설명되지 않으며, 데이터의 의미와 품질, 실패 시 추적 가능성, 기술 선택의 근거가 함께 있어야 한다는 점을 배웠습니다. 이후에는 실제 운영 지표를 축적해 품질 임계값과 파티션 설정을 조정하고, 재처리 절차를 자동화하여 프로젝트의 신뢰성과 유지보수성을 높이겠습니다.
