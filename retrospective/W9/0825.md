# 2026-08-25 회고

## Keep
- 원천 API의 응답 구조와 필수 컬럼, 갱신 주기, 누락 가능성을 조사하여 수집 단계의 데이터 계약을 정의하였다.
- 원본 응답과 수집 시각을 그대로 보존하도록 저장 경로와 파일 이름 규칙을 정해 이후 문제를 재현할 수 있게 하였다.

## Problem
- 정상 응답 예시만 기준으로 스키마를 정하면 빈 배열, 선택 필드 누락, 타입 변경과 같은 상황을 처리하기 어려웠다.
- 이벤트가 발생한 시각과 파이프라인이 수집한 시각을 구분하지 않으면 지연 데이터의 기준 날짜가 달라질 수 있었다.

## Try
- 필수·선택 필드와 허용 타입을 명시하고 계약을 벗어난 레코드는 원본과 오류 사유를 별도로 격리하겠다.
- Event Time과 Ingestion Time을 모두 기록하여 지연 수집과 재처리 시에도 같은 기준을 적용하겠다.
