# Week5 회고

5주차에는 Apache Spark의 핵심 데이터 처리 모델인 RDD와 DataFrame을 활용하며 분산 데이터 처리 방식과 Spark의 내부 동작 원리를 학습했습니다. RDD에서는 `map`, `filter`, `reduceByKey` 등의 Transformation과 Action을 직접 사용하며 데이터가 여러 파티션으로 나뉘어 처리되는 과정을 이해했습니다. 이후 DataFrame API를 활용해 데이터를 조회·변환·집계하고, `groupBy`, `join` 등의 연산을 수행하며 RDD보다 구조화된 방식으로 데이터를 처리하는 방법을 익혔습니다. 특히 `explain()`을 통해 Logical Plan과 Physical Plan을 확인하고 Catalyst Optimizer가 실행 계획을 최적화하는 과정을 살펴보면서, 동일한 데이터 처리 작업이라도 작성 방식과 실행 계획에 따라 성능이 달라질 수 있다는 점을 이해했습니다. 또한 캐싱, 파티션 조정, 브로드캐스트 조인 등 Spark에서 활용할 수 있는 여러 최적화 방법을 학습하며 단순히 코드를 작성하는 것뿐만 아니라 효율적인 분산 처리를 고려하는 경험을 할 수 있었습니다.

다만 Spark의 실행 계획을 확인하는 것과 실제로 어떤 부분이 성능 저하의 원인인지 판단하는 것은 별개의 문제라는 점을 느꼈습니다. 캐싱이나 파티션 수 조정, 브로드캐스트 조인과 같은 최적화 방법도 무조건 적용하는 것이 아니라 데이터의 크기와 처리 방식에 따라 선택해야 했고, 각각의 방법이 실제 실행 성능에 어떤 영향을 주는지 판단하는 것이 어려웠습니다. 또한 RDD와 DataFrame의 차이를 개념적으로 이해하는 것을 넘어 실제 상황에서 어떤 방식을 선택해야 하는지에 대한 경험이 아직 부족하다고 느꼈습니다. 다음 주차에는 실행 계획과 Stage, Task, Shuffle의 관계를 다시 정리하고, 데이터 크기와 연산 특성에 따라 적절한 최적화 방법을 선택하는 연습을 이어가겠습니다. 또한 Spark뿐만 아니라 Airflow와 같은 워크플로우 관리 도구를 활용하여 데이터 처리 작업을 안정적으로 실행하고 관리하는 방법까지 학습해 나가겠습니다.
