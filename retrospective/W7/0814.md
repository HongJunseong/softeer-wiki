# 2026-08-14 회고

## Keep
- Python UDF와 Spark 내장 함수로 같은 변환을 구현해 보며 Catalyst가 해석할 수 있는 표현식의 중요성을 알게 되었다.
- 내장 함수는 계획 최적화와 코드 생성의 이점을 활용할 수 있어 단순한 문법 선택이 성능 차이로 이어질 수 있음을 확인하였다.

## Problem
- UDF 내부 로직은 Catalyst가 파악하기 어려워 필터 재배치나 식 단순화 같은 최적화 기회가 제한되었다.
- 실행 시간만 한 번 비교해서는 JVM 준비 시간, 캐시 상태, 데이터 편차 때문에 구현 방식의 효과를 정확히 판단하기 어려웠다.

## Try
- 표현 가능한 로직은 SQL 함수와 DataFrame API를 우선 사용하고, UDF가 필요한 경우 선택 이유를 문서에 남기겠다.
- 성능 비교 시 입력 데이터와 캐시 조건을 통제하고 여러 번 실행한 중앙값과 실행 계획을 함께 기록하겠다.
