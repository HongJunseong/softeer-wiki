# 2026-08-13 회고

## Keep
- 데이터 크기와 정렬·파티셔닝 상태에 따라 Broadcast Hash Join, Sort Merge Join, Shuffle Hash Join이 선택되는 기준을 학습하였다.
- 테이블 통계와 `sizeInBytes`가 Cost-Based Optimizer의 조인 순서 및 물리 전략 선택에 영향을 준다는 점을 확인하였다.

## Problem
- 작은 테이블이라는 직감만으로 Broadcast Join을 기대했지만 통계가 없거나 부정확하면 원하는 전략이 선택되지 않았다.
- 조인 힌트를 주면 항상 빨라질 것이라고 생각했으나 실행기 메모리와 네트워크 비용을 함께 고려해야 했다.

## Try
- 조인 전후의 행 수, 데이터 크기, Shuffle 발생 여부를 측정한 뒤 힌트 사용 여부를 결정하겠다.
- 운영 데이터의 통계 갱신 시점을 관리하고, 예상한 조인 전략과 실제 Physical Plan이 일치하는지 검증하겠다.
